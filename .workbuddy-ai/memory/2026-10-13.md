## 5.6 + 5.7：解析移出 UI isolate + 真实进度 + 可取消（已完成）

commit 序列：`676d1ee`（阶段回报）→ `ce87b22`（isolate + 取消 + UI）

### 新增 `lib/apkparser/parse_task.dart`
- `ApkParseTask.start(path)` 派生 worker isolate；`task.events` 是有序 `Stream<ParseEvent>`；`task.cancel()` 是**真正终止**。
- 事件：`ParseStageReached` / `ParseOpenFailed` / `ParseFailed` / `ParseSucceeded` / `ParseCancelled`。
- `ParsedApkData { ApkMeta meta, Map<int, ResourceInfo> arscResources }` 跨 isolate 传递。
- **图标渲染留在主 isolate**：`ApkInfo` 持有 `dart:ui` 的 `Image`，不能跨 isolate 传。worker 只做纯计算（那正是卡 UI 的部分）。

### 关键取舍
- 取消用 `Isolate.immediate`，不是默认的 `beforeNextEvent` —— 后者要等 worker 回到事件循环，
  而 worker 绝大部分时间耗在一段同步 arsc 解析里，那恰恰是用户想取消的时刻。
  代价：立即终止不执行 `finally`，因此 **worker 内禁止创建临时文件/持有需显式释放的资源**（代码里写明了）。
- 进度只报阶段、**不报百分比**：各阶段耗时极不均匀，百分比是编的。
- XAPK/aapt2 路径仍走 `Process.run`，**不可取消** → 该路径下不显示取消按钮
  （未实现的功能不得出现伪可用按钮）。
- 取消 ≠ 失败：`ApkParseCancelledException` 单独成类型，UI 不弹错误提示。

### 测试经验
- 先用**探针测试**确认 `Isolate.spawn` 的 async 入口能跨越 await（三条消息都收到），
  再基于该结论实现 —— 避免把设计建立在猜测上。
- 取消测试用一个 4 MiB 条目，保证 worker 在 `cancel()` 时**确实还在忙**，
  否则测的是「取消已完成的任务」这种无意义场景。

### 分工：静态提取 vs 验证
规范 5.5 禁止自行实现签名算法并宣称权威结论，因此**包内只做静态提取**：
- `packages/ipa_parser` 回答「文件里有什么」；
- `lib/utils/ios_codesign_analyzer.dart` 回答「是否有效」，且**只以 `--verify` 退出码为准**。

`codesign -d` 的输出是**描述性信息**，不是结论 —— 实测确认它对一个签名已损坏的
bundle 照样退出 0 并打印内容。

### 三个必须区分的结论
- 有材料但没跑过工具 → `toolUnavailable`（显示「无法确认」）
- 连材料都没有 → `unknown`（**不是**「无效」，更不是「恶意」）
- 描述文件读不出来 → `FieldStatus.failed`（**不是** `absent`；那会把「读不到」说成「没有」）

### 踩到的真实行为（都写进了代码注释与审计文档）
1. **BER 不定长容器的 EOC 只能消费一次**。把「内容结束」与「本元素结束」混为一谈，
   父容器读到子元素的 EOC 时会误以为自己也结束了。真实描述文件的 `eContent` 后面
   还有证书与签名者信息 —— 提前收尾会解析出**被截断的 plist**（字段都在、长度不对，
   极难发现）。`_Tlv` 因此区分 `contentEnd` 与 `nextOffset`。
2. `codesign --verify` 退出码 **3** = 「密封完好但不满足指定要求」（ad-hoc 必然如此）。
   把非 0 一律读成「签名无效」会把正常的 ad-hoc 重签包说成被篡改。
3. **只认退出码会凭空报出「签名有效」**：路径指向 `/usr/bin/true` 也返回 0。
   因此退出码 0 还要求输出里出现 codesign 特有结论行。
4. `codesign -d --entitlements :-`（带冒号）才是原始 XML plist；裸 `-` 是人读格式。
   前者已被标记将来移除，所以解析失败只记「没读到」，不当成「没有授权项」。
5. `Sealed Resources version=2 rules=13 files=74` —— 键与等号之间还有内容。
   按「第一个等号」切分会得到假键，该字段永远为空。
6. **`git ls-files` 会漏掉未 `git add` 的新文件**，本地门禁通过、CI 才红。
   本次实际踩到三处。CI 与本地一律改用 `git ls-files -co --exclude-standard`。

### 授权比对
`application-identifier` = `<App ID 前缀>.<bundle id>`，`CFBundleIdentifier` 只有
`<bundle id>` —— **必须按后缀比较**。直接比字符串会让每一个正常应用都被判成
「授权的是别的应用」。通配符的结论是「覆盖」而非「确认」。

### 解包
`codesign` 需要磁盘上的 `.app`，所以必须解包。做法：先算后写（超限不写盘）、
逐条 `ZipGuard.safeJoin`、声明尺寸与实际不符即中止、按实际字节兜总量、
**不创建符号链接**（链接目标可以是 `../../..`）、取消与任何失败都清理临时目录。
