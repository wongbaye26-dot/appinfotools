## IPA 详情页 UI：修高度缺陷 + 与 Android 分开

用户要求：`@image 优化一下查看IPA应用页面的UI样式，要跟安卓APK区分一下`。
截图里的症状是一列高得离谱的卡片、标题飘在卡片正中间。

### 1. 根因是 `SelectableText` 的高度预留（真实缺陷）

`TitleValueLayout` 把 `maxLines` 直接传给 `SelectableText` 而**不传 `minLines`**。
实测（临时探针，已删）：

```
min=null max=6  单行=136px  五行=136px     ← 缺陷：预留了 6 行
min=1    max=6  单行=56px   五行=116px     ← 修复后
```

`maxLines: 1` 时是 39px，也就是说 136px 里绝大部分是空白。默认「最大行数」是 6，
于是所有单行卡片都高 136px。

修法：`minLines` 默认 1，并**夹紧到 `maxLines` 以内**（设置页允许把上限调到 0，
写死的 1 会触发 `assert(minLines <= maxLines)`）；交叉轴对齐 `center` → `start`。

Android 侧那些卡片本来就显式传了 `minLines: 1`，所以行为不变；iOS 侧没传，
这才是缺陷只在那半页显形的原因。

### 2. IPA 页与 Android 页分开

- 分组：文件信息 / 应用信息 / 容器与二进制 / 签名与授权 / 文件校验
- Hero 卡片：平台徽标 + 图标 + 应用名 + Bundle ID + 版本；图标诊断放底部通栏
- 标识符用等宽（`Menlo` / `Consolas`，不写 `'monospace'` —— 它在 macOS 上解析
  不到会静默退回比例字体）；强调色用固定的 iOS 系统蓝
- 签名结论与 codesign 拆成两张卡（`DetailRenderer.iosCodeSignBody` 是新增的
  不带表头版本，避免「codesign 验证  codesign 验证: 验证通过」）
- iOS 侧不设 `maxLines`：它是**裁剪**，超过的行根本不会被绘制，而这一页上超过
  六行的正是签名、容器清单、诊断

### 3. 把页面渲染成 PNG 逐张核对，又发现三个问题

用 `RepaintBoundary.toImage` + 加载系统字体（`Arial Unicode.ttf` / `Monaco.ttf`）
落成 PNG 来看。读代码和断言都发现不了的：

1. **「容器」卡片上印着函数对象**：`iosContainer` 调用
   `t.apk_info.structure_file_count` 漏了 `count:`，这个键带 `{count}` 占位符，
   slang 把它生成为方法，漏传不报错但会把函数插进字符串 → 界面上是
   `Closure: ({required Object count}) => String from Function ...`。
   既有测试断言的是 `contains('7')`，缺陷版本下也通过。
2. **分组标题渲染成蓝色色块**：`IosSectionHeader` 是唯一没有 `Material`/`Card`
   祖先的组件，用裸 `const TextStyle(...)`，`fontFamily` 靠环境继承 ——
   不在 Scaffold 里时继承到 `WidgetsApp` 的 `_errorTextStyle`（monospace +
   下划线 + w900），实测 13.3px/字符（正常约 6.2px/字符）。改为显式取
   `theme.textTheme.labelLarge` / `labelSmall`。
3. **没有 `Payload/*.app` 时一页短横线**：Hero 与每一组都是「-」，而「-」的含义
   是「文件里没有这一项」。新增 `ios_info.no_main_app` 在最前面说明原因。

顺带发现：测试里把 `APKInfoPage` 直接当 `MaterialApp.home`，真实树是在
`HomePage` 的 `Scaffold` 里 —— 前者会以报错样式渲染。已在新测试里对齐。

  绝对上限 60px）。**反向验证过**：恢复缺陷后 7 条里 5 条失败，报出 136 vs 39。
- `test/ios_detail_page_test.dart` —— 用**合成**的 iOS 结果，不依赖真实样本。

- `test/i18n_placeholder_usage_test.dart` —— 扫 `assets/i18n/en.json` 里带占位符

  把缺陷改回去，它精确报出 `lib/utils/detail_renderer.dart:389`。
