## 1. 侧边栏

### 1.1 宽度 240 → 200

导航项只有四个、标签最长两个字，240px 里近一半是空白，而右侧内容区为此少
40px。宽度抽成 `kSidebarWidth` 常量 —— 此前「240」散落在 `main.dart` 的注释
与 `overview_layout_test.dart` 的换算里。

**连带改到的**：`main.dart` 与 `app_shell.dart` 的注释、`overview_layout_test.dart`
里那三档「内容区尺寸」的说明（660 现在对应 860px 窗口，比最小窗口 900px 还窄
40px —— 这组尺寸刻意比真实情况苛刻）。

### 1.2 导航项「版本对比」→「对比」

`t.nav.diff`：`zh-CN/zh-HK/zh-TW` 由「版本对比 / 版本對比」改成「对比 / 對比」，
`ja` 由「バージョン比較」改成「比較」，`ko` 由「버전 비교」改成「비교」。
`en` 本来就是 `Compare`，未动。

**页面正文的标题（`t.diff.title`）仍是「版本对比」** —— 那里有足够的空间，
它也仍是这一页的正式名字。

### 1.3 不再显示应用名与版本号

同一件事此前在三个地方各说一遍：窗口标题栏「AppInfoTool v2.4.5」、侧边栏
顶部「AppInfoTool / 应用包分析工具」、侧边栏底部「v2.4.5」（紧凑模式下还是
竖排的）。现在：

- 窗口标题 → `AppInfoTool`（`windowManager.setTitle(t.title)`，**三平台同一行
  代码，Windows 一并生效**）；
- 侧边栏顶部 → **只有 logo**（居中留白，纵向还给导航项约 60px）；
- 侧边栏底部 → 只有「支持 Android / iOS」两个平台图标；
- 版本号仍然可以在**设置页**看到（`setting_page.dart` 一直有一份）。

### 1.4 顺带修掉一个死分支

响应式判据原本是 `LayoutBuilder` 的 `constraints.maxWidth < 800`。**侧边栏是
`Row` 的非弹性子项，而 `Row` 给非弹性子项的约束在主轴不设上限** —— 实测探针
（`Row` 内放一个 `LayoutBuilder`）看到的是：

```
BoxConstraints(0.0<=w<=Infinity, 0.0<=h<=800.0)
```

因此 `constraints.maxWidth` 恒为 `Infinity`，`< 800` 永远为假，**紧凑模式
（64px）是死代码**。改用 `MediaQuery.sizeOf(context).width`。

**这一条用户看不到差别**（最小窗口是 900px > 800 的分界），修的是「写了却
从没生效」。测试 `test/sidebar_test.dart` 现在真的能驱动到 64px 那一支。

## 2. 版本对比：两侧槽位加图标与平台标签

`_SlotCard` 现在左侧是 48px 的真实应用图标（与概览页 Hero 同一条取舍：
Android 用已渲染的 `dart:ui.Image` + `BoxFit.cover`，iOS 用图标候选走
`IosIconDecoder` 的 CgBI 规范化），右侧是文件名 + 平台标签 + 元信息。

**取不到时退回平台通用图标，不留空白框** —— 空白框会被读成「这个包没有图标」，
而真相是「我们还没拿到」。

平台标签抽成了共享组件 `lib/widgets/platform_tag.dart`：此前概览页的「最近
文件」自己写了一个 `_PlatformTag`，本页再写一遍就会漂移。「字符串 → 枚举 →
文案与颜色」的转换只在那一个工厂里做，散落的 `== 'android'` 写错了编译器不会
说话。

## 3. 重命名对话框统一

### 3.1 之前是什么样

**两个入口、两份几乎一样但不完全一样的实现**：

| | 概览页 Hero | 分析页「文件」行 |
|---|---|---|
| 默认名 | `应用名-版本.后缀`，取不到时退回原文件名 | 无条件拼 `'$displayName-$versionName$ext'` |
| 确认按钮 | `TextButton` | `TextButton` |
| 校验清单 | 手抄 `.apk/.xapk/.apkm/.apks/.ipa` | 同一份手抄（各自一份） |
| 提示文案 | 各写一遍 switch | 各写一遍 switch |

### 3.2 现在

只有一份实现：`lib/widgets/rename_file_dialog.dart` 的
`showRenameFileDialog` + `reportRenameOutcome`。版式与「导出报告」对话框对齐
（标题左侧带图标、内容固定 420px、上方一个只读的「当前文件」路径框、动作用
`TextButton` 取消 + `FilledButton.icon` 确认）。

**默认名逐级退化**：应用名 + 版本 + 原后缀 → 应用名 + 后缀 → **原文件名**。
最后一级是唯一一定成立的事实（此前会拼出 `--.apk`）。

**校验改用与「打开文件」同一份判定**（`isSupportedPackagePath`）：能打开什么
就能改成什么。此前手抄的清单漏了下载渠道加的 `.apk.1` 后缀 —— 那种文件**能
打开、却改不回去**。

**保存面板被取消时不关对话框**：用户还能改个名再试。关掉它等于把「我想改名
但选错了目录」变成「重来一次」。

## 4. 分析页「概览」：换位 + 架构位数

### 4.1 顺序

**应用信息 → 文件信息**（两侧一致）。用户打开一个包，第一眼要找的是「这是
哪个应用、什么版本」，而不是「它在磁盘上的路径」—— 后者是排查时才需要的。

Android 侧顺带补上「文件信息」分组标题：此前只有 iOS 有，Android 的文件 / 大小
两行直接裸挂在平台行下面，看不出属于哪一组。

**分组标题键从 `ios_info.group_file` 挪到 `file_info.group`**（6 个语言包都改），
因为两侧都要用它 —— 把一个通用概念放在 `ios_info` 命名空间里，Android 侧引用
它会让下一个人以为写错了。旧键已删（留一个没人引用的键更糟）。

还没解析出结果时，「应用信息」无从谈起，但**文件信息是事实**（路径与大小在
解析之前就知道了），照常显示。

### 4.2 32 / 64 位

概览页 Hero 里那段判定抽成 `lib/utils/architecture_label.dart` 的
`architectureLabelOf`，概览页与详情页共用 —— 此前它内联在一个 `build` 方法
里，没有任何测试能碰到它。

- **iOS**：主可执行文件 Mach-O 各镜像的 `is64Bit`（段位数，不是文件名里的字样）
- **Android**：容器里 `lib/<abi>/` 的 ABI 名（名字里带 `64` 的就是 64 位）

**四种结局都要能出来**：只 64 位 / 只 32 位 / **两者都有** / **取不到**。
最后一种返回 `null`，界面不显示这一项 —— 「不知道」与「32 位」是两件事。

`test/architecture_label_test.dart` 覆盖全部四种，iOS 用
`test/fixtures/macho/` 里的真实产物（clang 编译，期望值取自 `otool -hv`），
Android 用 `ContainerStructure`（它的 abis 本来就来自容器条目名）。

徽章样式抽成 `lib/widgets/arch_badge.dart`（原先是概览页里一个私有的
`_ArchChip`），放在版本号旁边而不是另起一行 —— 它是「这个包能不能装在老设备
上」的答案，属于同一眼的判断。
