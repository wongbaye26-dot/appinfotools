## 3. 任务清单与验收条件

### 任务 1：`ToolDownloader` 安全回归测试

**要验证的**：校验和解析、SHA-256 优先、SHA-1 回退、文件摘要计算、**校验不匹配时拒绝继续处理**。
**必须使用可控输入，不下载、不执行任何不可信二进制。**

**测试缝（需要决策，见 §5 待确认事项 Q2）**：相关函数**全是 `private static`**：

| 目标 | 位置 | 可见性 |
|---|---|---|
| `_parseChecksums(String)` | `tool_downloader.dart:472` | private static |
| `_digestFile(File, String)` | `tool_downloader.dart:544` | private static |
| `_verifyArchiveChecksum(...)` | `tool_downloader.dart:562` | private static |
| `_buildRepositoryIndexUrls()` | `tool_downloader.dart:105` | private static |
| `_selectPlatformTools(String)` / `_selectBuildTools(String)` | `:282` / `:303` | private static |
| `ArchiveInfo.preferredAlgorithm` | 公开 getter | **public**（可直接测） |
| `ToolDownloadError.checksumMismatch` | 公开枚举 | **public**（可直接测） |

**验收条件**

1. `_parseChecksums` 能从 `<checksum type="sha256">…</checksum>` 形态解析出 `{sha256: …}`；
   多种类型（sha1/sha256/md5）同时出现时全部取出。
2. **SHA-256 优先、SHA-1 回退**：同时存在时选 sha256；只有 sha1 时选 sha1；只有 md5 时选 md5；
   **一个都没有时不得选出一个「空算法」**。
3. `_digestFile` 对**已知内容的临时文件**算出的摘要与外部工具一致
   （期望值用 `shasum -a 256` / `openssl dgst` 独立核对，**不从本实现取**）。
4. **校验和不匹配 → 拒绝**：摘要与声明不符时抛/返回 `checksumMismatch`，**不继续解包**。
5. 索引**未提供校验和**时同样拒绝安装（「没有校验和」不等于「校验通过」）。
6. 全部用例**不产生任何网络请求**（测试中不得出现真实下载）。
7. 原有根测试与四个包级测试**无新增失败**。

### 任务 2：`xapk_installer` 安全测试

**要验证的**：解包调用路径中**每个文件条目都受现有 ZipGuard 约束**；
异常路径**不会写到目标目录之外**。**尽量复用现有夹具。**

**已核实的事实（本轮新增取证）**：守卫**已接入** ——
`xapk_installer.dart:162` 的 `_safeExtractJoin` 转发到 `ZipGuard.safeJoin`，
并在 `:223`（base/split APK 解包）、`:245`（批量分包路径校验）、`:284`（OBB 解包）
三处、**每个 `zip.extractFile(...)` 之前**调用。因此本任务的性质是**补回归保护**，
不是修缺陷。

**可测入口**：

| 入口 | 可见性 | 是否需要 adb |
|---|---|---|
| `getSplitApks(String xapkPath)` | **public** | 否（只开 ZIP、读 manifest、列条目、排序） |
| `_safeExtractJoin(String root, String entry)` | private | 否 |
| `install(...)` | public | **是**（调用 adb，本机无法验证） |

**验收条件**

1. 用**自造的极小 XAPK**（测试内构造 ZIP，不提交真实样本）验证：
   条目名为 `../../evil.apk` / 绝对路径 / 盘符 / UNC 时，**在写入前即被拒绝**，
   且**目标目录之外没有产生任何文件**。
2. 正常条目（`Android/obb/<pkg>/main.1.<pkg>.obb` 这类）**照常放行**——
   守卫不能把正常包也拦掉（边界成对断言，与 `archive_safety` 的做法一致）。
3. **源码级守卫**（本项目的既有做法，见 `info_page.dart` 的 `?? ""` 断言）：
   断言 `xapk_installer.dart` 里**每一个 `zip.extractFile(` 调用点之前都出现过
   `_safeExtractJoin(`** —— 防止将来有人新增一条未受守卫的解包路径。
4. `getSplitApks` 的行为回归：manifest 有分包列表时用它；没有时回退
   `listFiles(extension: '.apk')`；**base 排在最前**；都拿不到时返回 `null`。
5. `install(...)` **不在本任务的验证范围内**（需要 adb 与设备）—— 如实标注未验证。

### 任务 3：`ReportExporter` 测试

**要覆盖的**：成功 / 取消 / 失败**三态**；**entitlement 专用错误文案**与其他平台异常分支。

**已核实可测（本轮新增取证）**：`file_picker` 10.3.8 的 `FilePicker.platform` 是
**可写的静态字段**（`file_picker.dart:37` getter / `:39` setter），
`FilePicker` 是 `abstract class … extends PlatformInterface`，
因此测试里可以 `extends FilePicker` 造一个假实现并替换 —— **无需改生产代码**。

**验收条件**

1. 保存面板返回 `null` → `ReportSaveResult.cancelled`，
   **`isCancelled == true` 且 `failure == null`**（**取消不是失败**）。
2. 保存面板返回路径且写盘成功 → `.saved`，文件内容与传入的 `content` **逐字节一致**。
3. `PlatformException(code: 'ENTITLEMENT_REQUIRED_WRITE')` → `.failed`，
   且文案**等于** `t.report.save_error_entitlement`（不是复述错误码）。
4. `PlatformException(code: 'ENTITLEMENT_NOT_FOUND')` → 同上（两个码走同一分支）。
5. **其它** `PlatformException` → `.failed`，且文案走 `t.report.export_failed(error: …)` 分支
   （**不得**误用 entitlement 专用文案）。
6. 写盘抛 `FileSystemException`（如目标目录不存在）→ `.failed`，文案走 `export_failed`。
7. `allowedExtensions` 传入时，传给面板的 `type` 为 `FileType.custom` 且
   `allowedExtensions` 原样透传；**不传时为 `FileType.any`**（守住 v2.4.1 那次「没顺手丢掉」的修复）。
8. 三态互斥：任意一次调用的返回值**只可能落在一种状态**上。

### 13.4 一个容易漏的细节：插值不是占位符名
