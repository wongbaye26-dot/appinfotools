## 1. 详细信息不再重复 Hero 的信息

### 1.1 问题

Hero 上已经有：应用名、包名、`v1.4.1 (14102)`、完整文件路径（含文件名）、
架构位数、大小、签名、安全。而「详细信息」网格的 6 项是：

| 原 6 项 | 与 Hero 的关系 |
|---|---|
| **文件名** | **重复**（路径里就有） |
| **版本** | **重复**（`v1.4.1 (14102)`） |
| **构建号** | **重复**（同上） |
| 最低 SDK | 不重复 |
| 目标 SDK | 不重复 |
| SHA-256 | 不重复 |

正好三项重复 —— 与用户的说法一致。

### 1.2 换成什么

选的是「Hero 上没有、但打开一个包时一眼想知道」的：

| # | Android | iOS |
|---|---|---|
| 1 | 最低 SDK | 最低 OS |
| 2 | 目标 SDK | 设备类型 |
| 3 | ABI | 可执行文件 |
| 4 | 权限数 | 嵌套包数 |
| 5 | 组件数 | —（iOS 没有对应概念） |
| 6 | SHA-256 | SHA-256 |

**计数类字段读不到时不渲染**（`FieldValue.hasValue` 为假就整格不出现）——
「没读到」不能渲染成 0，那会被读成「一个都没有」。

新增 3 个文案键（`overview.field_permission_count` / `field_component_count` /
`field_nested_bundle_count`），6 个语言包都补了。

## 2. 标题样式：不再逐字折断

### 2.1 根因

`TitleValueLayout` 的标题列宽度取设置里的 `title_width`（默认 100），而
设置页滑块的下限是 **40**。在那个宽度下，一个 16px 的中文标签连一个字都
放不下，Flutter 只能**逐字硬折** —— 实测 `uiMode 设备类型` 变成
`uiMod` / `e 设备` / `类型` 三行。

（用户截图里的 `ICP 备案` 折成 `ICP 备` / `案` 是同一个原因。）

### 2.2 改动

1. **宽度夹紧到 96–200**（`kMinDetailTitleWidth` / `kMaxDetailTitleWidth`）。
   96 不是排版偏好，是「六字中文标签放得下」的下限。旧配置存 40 也按 96 排；
   滑块下限同步改成 96，否则界面上会显示 40、实际按 96 排版。
2. **标题绝不换行**：`softWrap: false` + `maxLines: 1` + 省略号，完整标题
   交给 tooltip。截断至少是单行、可预期。
3. **标题样式统一成「淡色小字」**（`bodySmall` + hint 色）。此前是 16px
   常规字重、与 14px 的值同色 —— 扫一眼分不出哪个是标签。
4. 设置页的「标题宽度」预览改用**同一个样式函数** `detailTitleStyle(context)`。
   此前预览里写死 `fontSize: 16`，只是恰好与卡片一致 —— 改一处另一处就成了
   谎言。

## 3. 应用图标尺寸统一

三处各写各的：

| 位置 | 尺寸 | 圆角 |
|---|---|---|
| 概览页 Hero | 92 / 76（紧凑） | 边长 × 0.2237 |
| **分析页 Hero 卡片** | **72** | **16（固定像素）** |
| 版本对比槽位 | 48 | 边长 × 0.2237 |

72 与 92 并排就露馅（用户的原话是「小了一点」）。圆角更糟：两处按比例、
一处固定 16px —— 改尺寸时圆角不会跟着变。

新增 `lib/widgets/package_icon_metrics.dart`（`PackageIconMetrics`）：
`heroSide = 92` / `compactHeroSide = 76` / `slotSide = 48` /
`radiusOf(side) => side * 0.2237`。三处都从它取。分析页的图标因此从 72 长到
**92**，圆角 16 → 20.6。

## 4. 版本对比左侧没有图标

### 4.1 根因：**生命周期**，不是渲染

- `CurrentApkInfo.update/reset` 在换文件时会 `state?.dispose()`；
- `ApkInfo.dispose()` 会把图标候选的 `ui.Image` 一起释放，并把
  `mainIconImage` 置空；
- `parsedFileCacheProvider` 里存的正是**同一个** `ApkInfo` 实例。

于是**先解析的那个包**（差异页左侧）图标消失，只有当前那个（右侧）还活着。
这解释了为什么「只有左边没有」。

iOS 侧不受影响：它的图标是从 `IpaAnalysis` 里的**字节**现解的，那份数据不会
被 dispose —— 所以只有 Android 需要修。

### 4.2 修法

新增 `parsedFileIconsProvider`（`lib/providers/parsed_file_cache.dart`）：
解析完成时给图标留一份 **`ui.Image.clone()` 副本**。克隆体共享底层像素、
各自计数，因此不受原对象 dispose 影响。

三个必须做对的细节：

1. **`AppShell.initState` 里要显式 `ref.read` 一次。** 它靠监听累积，而它
   只在「差异页真的画出槽位」时才被读到 —— 那时两个包的 `ApkInfo` 早被
   dispose 了。**这一行是整套修复的前提**，`test/package_icon_test.dart` 里
   有一条专门守它（去掉那一行测试立刻红 —— 已实测验证）。
2. **`ref.onDispose` 里不能读 `state`。** Riverpod 明确禁止在生命周期回调里
   碰 `state`（实测报 `Cannot use Ref or modify other providers inside
   life-cycles`），而那恰恰是要释放资源的地方。因此另存一份私有 `_icons`，
   `state` 只是给监听者的投影。
3. **只在第一次见到某个路径时克隆**：图标解析出来之后就固定了，重复克隆只是
   白占内存。克隆失败（原图已被释放）只记 `fine` 日志，界面退回平台通用
   图标 —— 那是一次没赶上，不是错误。
