## 1. 任务①：Hero 区显示文件路径 + 重命名

### 1.1 问题

路径此前只出现在「详细信息」网格里，而网格是**随窗口高度收起**的
（`_detailGridMaxHeight = 180` 只是门槛，`maxHeight < 90` 时整块
`SizedBox.shrink()`）。于是「这个包在磁盘上哪儿、我要改个名」这个最常见的
诉求，恰好在最小窗口（900×600）下看不见。

### 1.2 做法

路径挂在 Hero 的**「当前文件」那一行**上（等宽 11px、单行省略、悬停看全文），
右侧跟复制与重命名两个入口；原网格里的「文件路径」格子删掉，重命名入口因此
仍然只有**一个**。

**为什么不新开一行** —— 实测的数字不允许：

| 尺寸 | 页头 | Hero | 统计 | 最近文件（弹性） |
|---|---|---|---|---|
| 660×600（最小窗口） | 58 | 332 | 104 | **46** |
| 1040×800（默认窗口） | 58 | 459 | 104 | **73** |

最近文件区自身至少要 26px（分区标题 20 + 间距 6），默认窗口下只多出 47px。
新开一行要 19px，而 Hero 的行高由 `IntrinsicHeight` 取「图标 92px」与
「文字列」的较大者 —— 加一行会让文字列反超图标，Hero 真的长高。
**实测过一次：新开一行后默认窗口溢出 14px、最小窗口溢出 4px。**
挂在已有那一行上是**零高度成本**，且「当前文件」旁边正是它该在的位置。

### 1.3 一个必须记下来的坑：`CopyIconButton` 的**固有高度**是 40px

第一版把路径行做成独立的 `Row`，其中放了 `CopyIconButton` 与一个 `IconButton`。
两者都写了 `constraints: const BoxConstraints()`，**实际布局**确实只有 13px 高；
但 `IntrinsicHeight` 量的是**固有高度**，M3 的 `IconButton` 在那里报的是 40px
（最小点按尺寸）。结果整个身份行从 **96px 被撑到 120px**，固定一屏的概览页
立刻溢出。

- 现象：`RenderFlex overflowed by 14 pixels on the bottom`，溢出点是
  「最近文件」的空状态。
- 定位手法：拿 HEAD 版本的 `overview_page.dart` 跑同一条测试作为对照，
  再用一个临时探针打印 `IntrinsicHeight` 的尺寸（96 vs 120）。
- 结论：`constraints` 压得住布局，压不住固有高度。凡是放进
  `IntrinsicHeight` 的行，**高度必须自己钉死**（`_FilePathLine._lineHeight`），
  文案的 `height: 1.1` 是为了让 11px 的行盒落进这个高度。

### 1.4 验收

`test/overview_layout_test.dart` 新增一组「Hero 的文件路径行常驻且可重命名」：

- 最小 / 默认 / 宽**三个尺寸**下，完整路径与重命名按钮都在；
- 点重命名按钮真的弹出对话框，默认名按「应用名-版本号.后缀」生成，
  取消能关掉；
- 三个尺寸下**都不得溢出**（原有那组测试不变，仍绿）。

## 2. 任务②：解析速度

### 2.1 基线（实测，`sun_signed.ipa`，40.5 MB，326 个条目）

探针：`tool/perf_probe_test.dart`（**不属于**质量门禁，默认 `flutter test`
不会跑到它）。

```
1. 打开归档（中央目录 + 预算判定）        16.1 ms
2. 枚举 bundle                          3.6 ms
3. Info.plist                          6.1 ms
4. 图标定位                             2.2 ms
5a. 主可执行文件读取                     76.9 ms
5b. 主可执行文件 Mach-O 解析              4.7 ms
6a. 嵌套 bundle 读取（27 个）            92.6 ms
6b. 嵌套 bundle Mach-O 解析             19.5 ms
7. 签名材料                            30.1 ms
★ 完整静态解析（open + analyze）        155.4 ms
8. 三种哈希（独立 isolate）             653.3 ms   ← 最大单项
9a. 解包主 .app 到临时目录               277.0 ms
9b. 解包 + codesign（完整一步）          348.5 ms
```

**结论先行**：静态解析只要 155ms，**哈希 653ms 才是最大单项**（占整条链路的
一半以上）。改解析器内部的算法没有意义 —— 那 155ms 里没有可砍的重复计算。

### 2.2 哈希拆分（10 核机器）

| 做法 | 耗时 |
|---|---|
| md5 单跑 | 192.9 ms |
| sha1 单跑 | 221.5 ms |
| sha256 单跑 | 292.2 ms |
| 串行三趟 `Isolate.run`（原实现口径） | **622.5 ms** |
| 三 isolate 并行 | **272.8 ms**（2.28×） |

原实现是「一趟读文件、三种算法串行更新」。改成**三种算法各跑一个 isolate**
之后：文件被读三遍，但那三遍都命中页缓存；瓶颈本来是摘要的 CPU 计算，
不是 IO。**实测 653.3 → 298.2 ms。**

正确性用系统工具独立核对（`md5` / `shasum`），**不从本项目代码取期望值**：
小文件（28 B，单分块内）与大文件（10 MiB + 12345 B，跨分块且**不是分块整数倍**）
各一组，见 `test/file_hash_test.dart` 与 `test/fixtures/hash/README.md`。

### 2.3 另外两处重复计算

- `ApkInfo.collectIconCandidates` 里用 `List.contains` 判断候选路径是否在归档中
  —— 候选有几十个、条目动辄几千条。改成一次建 `Set`，之后 O(1)。
- `ApkParseTask` 的成功路径上 `reader.scanHardeningSignals()` 被调了**两次**
  （一次喂审计、一次进结果），每次都要遍历整张条目表。改成算一次复用。

### 2.4 未做（明确记下来，不含推测）

- **APK 侧没有基线**：仓库里只有 4 个 1–2 KB 的合成 APK，没有真实样本，
  因此上面两项改动的收益**没有实测数字**，只能说「去掉了明确的重复计算」。
- **`getApkInfo` 在主 isolate 上为图标重新打开一次归档**（`ApkInfo.loadIcon`）
  —— 这是同步的中央目录解码，跑在 UI 线程上。真实大 APK 上可能是可感知的
  卡顿，但要改成「把图标读取挪进 worker」需要重排 `dart:ui` 与 isolate 的
  边界（`Image` 不能跨 isolate），**本轮不动**。
- **解包 + codesign 的 348ms 里，48ms 是第二次打开归档**（worker 里的那次
  已经随 worker 结束）。要省掉它就得让 worker 往磁盘写临时目录，而那正是
  `Isolate.immediate` 终止会留垃圾的地方 —— 设计上刻意排除，**不碰**。
- **渐进式呈现**（先把 Info.plist + 图标给界面，再补嵌套 Mach-O）才是体感上
  最大的改动，属于结构重构，**本轮不做**。

## 3. 任务③：最近文件的真实图标与平台信息

### 3.1 做法

- **图标在「解析成功那一刻」顺手缓存**，不是列表按需去开归档。
  Android 用已经渲染好的 `mainIconImage`，iOS 用刚解出来的候选
  （`IosIconDecoder.decode`）—— 两边都已经在手上。
- 缓存为 **96px 的 PNG**，落在 `<应用支持目录>/recent_icons/`。
  96px 是按「列表里显示 32px、2x/3x 屏幕」定的；再大只是白占内存 ——
  列表一次可能画 10 行，512px 的原图解码就是 10MB 级别的位图。
- 文件名 = `sha1(源路径 + 体积)`。**带上体积**是为了让被替换过的同名文件拿到
  新图标；只按路径做键的话，用户重新下了一个同名的包，列表里还是旧图标。
  存**文件名**而不是绝对路径：缓存目录的位置随平台与用户变。
- 列表被挤出去的记录，其图标文件在下次写入时清掉（`RecentIconCache.prune`）。
- 一切失败都是非致命的：取不到缓存就退回平台通用图标。
  `path_provider` 不可用（测试环境）时只记一条 `fine` 日志，且**失败也记住**，
  不然 10 行会各抛一次异常。

### 3.2 平台信息用文字

此前只有一个 16px 的通用图标（Android 小绿人 / iOS 苹果），平台靠认图标猜。
现在每个包的图标都不一样了，不写文字就分不出来。标签是**文字 + 颜色**，
不是只有颜色 —— 只靠颜色区分在色觉障碍下等于没有区分（与详情页同一条约定）。

### 3.3 验收

`test/recent_files_icon_test.dart`：条目字段往返、旧数据（没有 `iconFile`）
解析成 `null` 而不是抛错、缓存文件名稳定且换体积会换名、带分隔符的文件名被拒
（防目录穿越）、三个尺寸下列表行都渲染出平台标签与通用图标且不溢出。
