# AppInfoTool 2.11.1 实机验收清单（Windows / Linux / iOS 真机）

日期：2026-11-28
用途：补齐 `APPINFOTOOL_2.11.1_RELEASE_ACCEPTANCE.md` 里仍为 **FAIL / PARTIAL** 的三项
（门禁 4 Windows/Linux 实机、门禁 2/8 的 iOS 侧、iOS 真机安装）。
本文件只负责「怎么跑、记什么」，不预设结论；跑完把结果写回验收文档。

## 0. 共通准备

| 项目 | 要求 |
| --- | --- |
| 构建来源 | 同一个 commit 的 CI 产物（`v2.11.1` 候选 tag 的 run，或本地 `flutter build`），在「环境记录」里写清 |
| 测试包 | 至少 2 个真实 APK（1 个普通、1 个加固/大包）+ 1 个 XAPK + 1 个 IPA；记录文件名与 SHA-256 |
| 记录方式 | 每条检查项记 `通过 / 失败 / 未执行`，失败必须附截图或日志，不允许只写「看起来正常」 |
| 失败即停 | 出现 P0 级失败（打不开、崩溃、导出文件损坏）先停止，把日志带回，不要继续刷其余项 |

### 环境记录（每个平台一份）

| 字段 | 填写 |
| --- | --- |
| 平台 / 版本 | 例：Windows 11 23H2 (22631.4169) / Ubuntu 24.04.1 LTS |
| 构建产物 | 例：`AppInfoTool-2.11.1-Windows-x86_64-Setup.exe`（sha256 …） |
| 安装方式 | 安装包 / 免安装 zip / AppImage |
| 显示缩放 | 100% / 125% / 150%（会影响 V4 布局断点，必须记录） |
| 执行人 / 日期 | |

## 1. Windows 11 验收

### 1.1 启动与主界面
- [ ] 安装包可安装、可卸载；开始菜单/桌面快捷方式能启动
- [ ] 首次启动无缺 DLL、无白屏；窗口最小尺寸下不溢出（拖到 760×520）
- [ ] 侧边栏、顶栏、概览页与 macOS 版视觉一致（卡片间距、圆角、字体回退正常）
- [ ] 中文界面无方块/乱码；切换 日本語 / 한국어 后文案完整

### 1.2 解析与页面
- [ ] 拖入真实 APK → 概览出现应用名、包名、版本、签名、风险计数
- [ ] 清单 / 组件 / 权限 / 库识别 / 签名 / 文件 / 诊断 七个 Tab 均可打开且无异常滚动
- [ ] 库识别显示 SDK 名称与图标（内置 197 个 SVG，缺失时应回退首字母块而不是空白）
- [ ] 权限页保护级别为中文，tooltip 含 `0x…` 与标志位
- [ ] 签名页显示证书 subject/serial/有效期/三种指纹
- [ ] 拖入 XAPK → 能解析分包信息；拖入 IPA → 能显示 Info.plist 与证书链
- [ ] 打开损坏包 / 非安装包文件 → 明确报错，不崩溃、不静默

### 1.3 导出
- [ ] 导出 Markdown：权限分级表、库识别小节、证书字段齐全，中文不乱码
- [ ] 导出 JSON：`reportSchemaVersion` 为 11，用 `docs/contracts/analysis-report-v11.schema.json` 校验通过
- [ ] 导出 HTML：能离线打开、样式完整
- [ ] 导出到含空格/中文的路径不失败

### 1.4 系统集成（Windows 专有）
- [ ] 资源管理器显示应用图标（缩略图处理器）：安装后生效；未安装工具时明确提示而不是崩
- [ ] `.apk` / `.ipa` 文件关联：双击能拉起本应用并打开该文件
- [ ] 设置 → 诊断与日志：导出诊断日志、打开日志目录、清理缓存均可用

### 1.5 安装到设备（Android）
- [ ] 连接 Android 设备，`adb devices` 可见后应用能列出设备（显示 ABI、可用空间、序列号）
- [ ] 安装 APK 成功；分包 APK 能选择并安装；日志实时滚动
- [ ] 勾选 `-r` / `-d` / `-t` 分别生效；安装失败时错误原因中文化
- [ ] 最近安装表记录成功与失败，重启应用后仍保留

## 2. Ubuntu 24.04 验收

### 2.1 启动
- [ ] AppImage 可执行（`chmod +x` 后双击或命令行），无缺库报错
- [ ] Wayland 与 X11 各启动一次（记录会话类型）；缩放 125%/150% 下布局不溢出
- [ ] 中文字体渲染正常（无豆腐块）；深色/浅色主题切换正常

### 2.2 解析与页面
- [ ] 与 Windows 1.2 相同七项全部通过
- [ ] `aapt2` 未安装时：APK 仍能解析（内置解析器优先），界面不得显示「需要 aapt2」才能用
- [ ] 设置 → 工具路径：未检测到 aapt2/apksigner 时提示可下载，下载后可用

### 2.3 导出与安装
- [ ] 导出 Markdown / JSON / HTML 同 Windows 1.3
- [ ] `adb` 可用时安装流程同 Windows 1.5
- [ ] 无 `adb` 时给出明确提示，不阻塞其它功能

## 3. iOS 真机验收（macOS 执行）

前置：一台已信任的 iOS 设备、`brew install libimobiledevice ideviceinstaller`、一份**已签名且允许安装**的 `.ipa`（自签/企业签均可，需写清签名方式）。

- [ ] `idevice_id -l` 能看到 UDID；应用「安装」页选中 IPA 后能列出设备（名称 / iOS 版本 / 机型）
- [ ] 点「安装」后日志实时显示 `ideviceinstaller` 输出，成功/失败结论与命令行一致
- [ ] 失败场景（未签名 / 描述文件不含该设备）日志原样保留错误码，不吞错
- [ ] 安装成功后设备上出现应用；记录 Bundle ID 与版本
- [ ] IPA 文件条显示应用名、Bundle ID、版本（Build），与 Info.plist 一致

## 4. 结果回收

1. 在本文件对应平台小节勾选，并在每节末尾填「结论：通过 / 不通过（原因）」。
2. 把平台、构建 SHA、执行人、失败截图路径写入 `APPINFOTOOL_2.11.1_RELEASE_ACCEPTANCE.md`：
   - 门禁 4：Windows 与 Ubuntu 两节都通过才可改 **PASS**；
   - 门禁 2/8：iOS 真机安装通过后，把「iOS 未覆盖」改为「真机人工验收通过」，CI 侧仍需一份可再分发 `.ipa` 才能把 `APPINFOTOOL_REQUIRED_SAMPLE_PLATFORMS` 改回 `android,ios`。
3. 三项都清零后，用新 commit 打 `v2.11.1` tag，确认 `external-samples` 真实执行、`create-release` 成功，再把验收结论改为 **GO**。

## 5. 判定规则

- 任一 P0（启动失败、解析崩溃、导出损坏、安装流程崩溃）→ 本次验收 **不通过**；
- P1（某平台专有功能不可用，如缩略图、文件关联）→ 记录为「已知缺口」，由产品决定是否阻塞发布；
- 未执行的项一律标「未执行」，不得折算为通过。
