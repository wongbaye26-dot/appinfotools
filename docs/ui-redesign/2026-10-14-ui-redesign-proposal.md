# AppInfoTool V2.0 UI 重设计方案

> 目标：从「数据表格」升级为「现代化桌面工具」的界面体验。

## 一、设计目标

1. **降低认知负荷**：当前详情页全是等权重的 Card，信息没有主次，用户难以一眼找到关键内容
2. **建立视觉层次**：通过大小、颜色、间距区分信息优先级
3. **统一平台体验**：Android/iOS 两页版式对齐但视觉可区分，不是靠颜色而是靠结构
4. **增强功能可见性**：安全检测、签名状态等核心结论需要更突出的视觉表达
5. **支持明暗模式**：现代桌面应用的基础能力

## 二、信息架构重组

### 当前架构问题

```
HomePage (AppBar + IndexedStack)
├── APKInfoPage (ListView + 20+ 张 Card)
│   ├── 平台标识
│   ├── 文件信息（4张卡）
│   ├── 应用信息（4张卡）
│   ├── 版本/SDK（2张卡）
│   ├── 权限（1张卡）
│   ├── 组件（1张卡）
│   ├── 加固线索（1张卡）
│   ├── 容器结构（1张卡）
│   ├── 签名（1张卡）
│   ├── 安全检测（1-2张卡）← V1.1 新增
│   └── 诊断（1张卡）
├── APKInstallPage（占位）
└── SettingPage（ListView + 5个 ExpansionTile）
```

所有信息平铺，没有折叠/展开机制，首屏只能看到前 6-8 张卡。

### 新架构

```
AppShell (侧边栏 + 主内容区)
├── 概览页 / Overview（默认页）
│   ├── Hero 区域（图标 + 应用名 + 版本 + 平台徽章）
│   ├── 关键指标行（文件大小 / 签名状态 / 安全等级 / SDK）
│   └── 最近文件列表
│
├── 详情页 / Details（原 info_page 重组）
│   ├── 顶部固定：Hero 摘要（折叠后保留）
│   ├── Tab 导航：
│   │   ├── 基本信息（文件 + 应用 + 版本）
│   │   ├── 权限与组件
│   │   ├── 容器与二进制
│   │   ├── 签名与安全 ← 合并签名+安全检测
│   │   └── 诊断与日志
│   └── 底部：操作栏（导出报告 / 重命名 / 打开目录）
│
├── 安装页 / Install（保留占位）
└── 设置页 / Settings（侧边栏入口）
```

## 三、设计系统规范

### 3.1 布局系统

```
+--------------------------------------------------+
|  AppInfoTool                              [_][o][x]  |
+--------+-----------------------------------------+
|        |  [Hero: 图标 应用名  v1.2.3  Android]      |
|  概览   |  [指标: 12MB | 签名通过 | P1风险 | API 34] |
|  详情   |                                           |
|  安装   |  [Tab: 基本信息 | 权限 | 容器 | 签名 | 诊断] |
|  设置   |                                           |
|        |  [Card 组...]                              |
+--------+-----------------------------------------+
```

- **侧边栏宽度**：200px（固定），折叠后 64px（仅图标）
- **主内容区**：最大 1200px 居中，响应式
- **内容内边距**：24px（桌面）/ 16px（紧凑）
- **卡片间距**：16px

### 3.2 颜色系统

在现有 Material 3 Seed Color 基础上扩展：

| Token | 用途 | Light | Dark |
|---|---|---|---|
| `surface` | 页面背景 | `#FAFAFA` | `#1A1A1A` |
| `surfaceContainer` | 卡片背景 | `#FFFFFF` | `#242424` |
| `surfaceContainerHigh` | 侧边栏背景 | `#F0F0F0` | `#1E1E1E` |
| `primary` | 主题色（种子色） | 种子色 600 | 种子色 400 |
| `onSurfaceVariant` | 次要文字 | `#5F5F5F` | `#A0A0A0` |
| `outlineVariant` | 分割线 | `#E0E0E0` | `#333333` |

**安全等级专用色**（与主题色隔离，语义固定）：

| 等级 | 色值 | 背景 | 用途 |
|---|---|---|---|
| P0 严重 | `#DC2626` | `#FEE2E2` | 红色 |
| P1 高风险 | `#EA580C` | `#FFEDD5` | 橙色 |
| P2 中风险 | `#CA8A04` | `#FEF9C3` | 琥珀 |
| P3 低风险 | `#16A34A` | `#DCFCE7` | 绿色 |
| INFO | `#2563EB` | `#DBEAFE` | 蓝色 |
| UNKNOWN | `#6B7280` | `#F3F4F6` | 灰色 |

### 3.3 字体系统

在现有平台字体基础上增加层级：

| 层级 | 大小 | 字重 | 用途 |
|---|---|---|---|
| Display | 28px | 600 | Hero 应用名 |
| Headline | 20px | 600 | 页面标题 |
| Title | 16px | 600 | 卡片标题 / Tab 标签 |
| Body | 14px | 400 | 正文 / 字段值 |
| Label | 12px | 500 | 字段标签 / 徽章文字 |
| Mono | 13px | 400 | 包名、ID、哈希等标识符 |

### 3.4 间距系统（8px 基准）

```
xs = 4px   // 图标与文字间距
sm = 8px   // 组件内部 padding
md = 16px  // 卡片内部 padding
lg = 24px  // 卡片间距
xl = 32px  // 区块间距
xxl = 48px // 页面级间距
```

## 四、各页面详细设计

### 4.1 侧边栏导航（新增）

```
+--------+
| AppInfoTool  ← 应用图标 + 名称（折叠后只留图标）
|--------|
| 概览    ← Icons.dashboard_outlined
| 详情    ← Icons.description_outlined  ← 当前激活：填充图标 + primary 色
| 安装    ← Icons.install_mobile_outlined
```

## 六、交互设计

### 6.1 文件打开流程

1. 用户拖放/选择文件
2. 显示解析进度（顶部进度条 + 阶段标签）
3. 解析完成后，自动切换到「概览页」
4. 概览页 Hero 区域显示应用信息
5. 用户可点击「详情」进入标签页查看完整信息

### 6.2 导航流程

```
[打开文件] → 概览页（自动）
    ↓
[点击详情] → 详情页（默认「基本信息」Tab）
    ↓
[点击签名与安全 Tab] → 查看签名 + 安全检测结果
    ↓
[点击导出] → 导出 Markdown / JSON 报告
```

### 6.3 响应式行为

| 窗口宽度 | 布局 |
|---|---|
| ≥ 1200px | 侧边栏 200px + 内容区 1000px |
| 800px - 1199px | 侧边栏 200px + 内容区自适应 |
| 600px - 799px | 侧边栏折叠为 64px（仅图标） |
| < 600px | 底部导航栏（移动端模式） |

## 七、实现路线图

### Phase 1：基础框架
1. 创建 `AppShell`（侧边栏 + 主内容区路由）
2. 实现 `NavigationRail`（桌面）/ `BottomNavigationBar`（移动端）
3. 创建空页面占位（OverviewPage、DetailsPage、InstallPage）

### Phase 2：设计系统
1. 扩展 `ThemeData`：添加明暗模式、安全等级色
2. 创建通用组件：`MetricCard`、`HeroBanner`、`FindingCard`、`EmptyState`
3. 实现字体层级（Display/Headline/Title/Body/Label）

### Phase 3：页面实现
1. 概览页：Hero + 指标卡 + 操作按钮 + 最近文件
2. 详情页：Tab 导航 + 各 Tab 内容迁移
3. 设置页：分组卡片重构

### Phase 4：迁移与清理
1. 移除 `HomePage` 的 `IndexedStack` 和 `AppBar` 动态注入
2. 移除旧的 `TitleValueLayout`（或保留作为详情页内部组件）
3. 统一所有页面使用新的 `AppShell`

## 八、风险与取舍

1. **Breaking Change**：这是一次大规模 UI 重构，所有页面结构都会改变
2. **测试影响**：UI 测试需要重写，尤其是 `test/real_samples_ui_test.dart`
3. **i18n 工作量**：新增「概览页」「详情页」等导航标签需要六语言翻译
4. **向后兼容**：设置项（如 `titleWidth`）在新设计下可能不再需要，需要迁移策略
