## 1. 权限数据

### 1.1 `generated.rs` 的真实结构（2228 行，84,882 B）

文件头两行即说明来源，别指望它有别的表：

```rust
// @generated by scripts/gen-android-data.py
// 数据来源：android-37.0 的 android.jar（权限）、ICU（语言自称）
```

全文件**只有两张静态表**：

```rust
// generated.rs:5
pub(super) static PERMISSIONS: &[(&str, u32)] = &[ /* 1102 项，行 6–1766 */ ];

// generated.rs:1768
pub(super) static AUTONYMS: &[(&str, &str)] = &[ /* 459 项 */ ];
```

- 名字按字节序排序（`binary_search` 在 `mod.rs:77–82` 直接依赖），由测试 `tables_are_sorted_for_binary_search`（`crates/core/src/android/mod.rs:231`）守住。
- `u32` 是 **android.jar 里 `android:protectionLevel` 的原始整数**，不是枚举字符串，也不做任何归一化。
- 表里**没有**：标题、说明、风险分组、API 级别、特性说明、语言名。这些在别处（见 1.5–1.8）。

### 1.3 风险分级（`mod.rs:84–152`）——这是**参考实现的策略**，不是 AOSP 数据

```rust
// mod.rs:89–102；声明顺序即 Ord，也就是展示优先级
pub enum PermissionRisk { High, Sensitive, Normal, System, Unknown }
```

排序依赖声明顺序，`risk_order_puts_high_first`（`mod.rs:289–294`）断言 `[High, Sensitive, Normal, System, Unknown]`；权限页用 `rows.sort_by_key(|r| r.risk)`（`crates/app/src/ui/pages.rs:675`）稳定排序，同风险内保持清单顺序。

```rust
// mod.rs:105–122  16 条高风险（可以读取隐私数据 / 可能产生费用）
const HIGH_RISK: &[&str] = &[
    "ACCESS_BACKGROUND_LOCATION", "ANSWER_PHONE_CALLS", "BODY_SENSORS",
    "BODY_SENSORS_BACKGROUND", "CALL_PHONE", "MANAGE_EXTERNAL_STORAGE",
    "PROCESS_OUTGOING_CALLS", "READ_CALL_LOG", "READ_CELL_BROADCASTS",
    "READ_CONTACTS", "READ_PHONE_NUMBERS", "READ_SMS", "RECEIVE_MMS",
    "RECEIVE_SMS", "RECEIVE_WAP_PUSH", "SEND_SMS",
];
// mod.rs:127–134  6 条"敏感但危险级别不是 dangerous"的特例
const SENSITIVE_SPECIAL: &[&str] = &[
    "MANAGE_MEDIA", "PACKAGE_USAGE_STATS", "QUERY_ALL_PACKAGES",
    "REQUEST_INSTALL_PACKAGES", "SYSTEM_ALERT_WINDOW", "WRITE_SETTINGS",
];
```

判定函数（`mod.rs:136–152`）逻辑等价于：

```text
若名字不在 PERMISSIONS           → Unknown（UI 显示"非框架"）
否则若短名 ∈ HIGH_RISK          → High
否则若短名 ∈ SENSITIVE_SPECIAL  → Sensitive
否则 base == Dangerous          → Sensitive
否则 base == Normal             → Normal
否则（Signature / SignatureOrSystem / Internal）→ System
```

对 1102 条全表与 143 条有文案的目的分布：

| 风险 | 全表（1102） | 有文案的（144 个短名） |
|---|---|---|
| High | 16 | 15 |
| Sensitive | 35 | 32 |
| Normal | 106 | 72 |
| System | 945 | 25 |
| Unknown | 0 | 0 |

**注意**：`READ_CELL_BROADCASTS` 在 `HIGH_RISK` 里但没有文案（16 vs 15 的差）。`dangerous` ≠ 高风险：`CAMERA`、`RECORD_AUDIO`、`POST_NOTIFICATIONS`、`ACCESS_FINE_LOCATION` 都落在 Sensitive，这是刻意的产品判断。

### 1.4 条目编码：名字 + maxSdkVersion

```rust
// mod.rs:155–164
```

### 1.6 生成脚本 `/tmp/ApkInfoPlus/scripts/gen-android-data.py`（257 行）

**输入**：`--jar PATH`，或自动挑 `$ANDROID_HOME` / `$ANDROID_SDK_ROOT` / `~/Android/sdk` 下版本号最大的 `platforms/android-*/android.jar`（`find_jar` 52–62）。运行环境要求 `aapt2` 与**带完整 ICU 的 node**。

**抽取三步**：

1. `aapt2 dump resources <jar>`（`parse_resources` 75–92）→ `{资源 id: {限定符: 字符串}}`，只留 string 资源；限定符从 `(zh-rCN)` 前缀形式取。
2. `aapt2 dump xmltree --file AndroidManifest.xml <jar>`（`parse_permissions` 95–123）→ 取 `E: permission (` 元素，字段 `name` / `protectionLevel`（十六进制整数）/ `label` / `description`（`@0x...` 资源引用）。按 name 去重保留第一条（注释说明：featureFlag 变体），按 name 排序。
3. Node `Intl.DisplayNames`（`icu_names` 163–167 + `ICU_JS` 126–160）→ 枚举全部 2/3 字母语言码（676 + 17576）与 2 字母大写/001–999 数字地区码，只保留 ICU 认识的（英文名存在且 != 代码）。每 UI 语言输出 `lang_name` / `region_name`（`style: short`，回退 `long`）/ `script_name`（`SCRIPTS` 42 项，45–49）。

**输出**：`generated.rs` + 6 个 `crates/app/i18n/android/<ui>.toml`。

**关键实现细节**：

- `UI_LANGS`（34–41）：`zh-CN→zh-rCN`、`en→""`、`zh-TW→zh-rTW`、`zh-HK→zh-rHK`、`ja→ja`、`ko→ko`。
- 只对 `android.permission.` 前缀的权限写文案（`PERM_PREFIX` 过滤，232）；key = 去掉前缀的常量名。
- `pick(res_id)`（217–219）= `vals.get(qual) or vals.get("")`：**缺失翻译静默回退英文**，所以每语言 key 集合永远齐全。
- `lang_name` / `region_name` / `script_name` 三节与英文合并（247），同样保证 key 集合一致。
- `toml_str`（170–173）把 `{` 双写成 `{{`（windui 占位符语法）——**从这些 toml 拷文案到 Dart/ICU MessageFormat 时必须反向去双花括号**。
- `unescape`（70–72）处理 `\uXXXX`、`\n`→空格、`\'` `\"` `\\`。

```rust
fn permission_text(section: &str, name: &str) -> Option<Message> {
    let short = name.strip_prefix(PERM_PREFIX)?;          // 非框架权限直接 None
    let key = format!("{section}.{short}");               // "perm_label.CAMERA"
    has_key(&key).then(|| Message::new(key))              // 惰性 Message，切语言自动跟随
}
```

## 3. 签名数据

### 3.1 核心事实：只解析证书，**不验签**

`signature.rs:1–3` 的文件头就是产品承诺：

> 只提取并解析证书，不验证摘要与签名——目标是把「谁签的」展示出来，而不是替代 apksigner。

对应 UI 文案 `signature.note`：
zh-CN `"以上信息来自 APK 内嵌证书的解析，未执行完整性校验。"`
en `"Parsed from the embedded certificates; integrity has not been verified."`

### 3.2 数据结构（`crates/core/src/info.rs:193–239`）

```rust
// info.rs:195–207
pub struct SignerInfo {
    pub subject: String,        // "CN=..., OU=..., O=..., C=.."（DN 倒序，同 keytool）

    pub not_before: String,     // ASN.1 时间字符串，如 "2024-01-01 00:00:00.0 +00:00"
```

### 3.3 证书定位（`crates/core/src/signature.rs`）

常量（13–18）：

```rust
const APK_SIG_BLOCK_MAGIC: &[u8; 16] = b"APK Sig Block 42";
const V2_ID: u32 = 0x7109_871a;
const V3_ID: u32 = 0xf053_68c0;
const V31_ID: u32 = 0x1b93_ad61;
const STAMP_V2_ID: u32 = 0x6dff_800d;   // v4 相关，只置 has_v4_stamp
const STAMP_V1_ID: u32 = 0x2b09_189e;
```

**v2 / v3 / v3.1 路径**（`parse_file` 26–49 + `read_signing_block` 119–193）：

1. 从文件尾读 `min(len, 65535+22)` 字节，**倒序**扫 `0x06054b50`，要求 `i+22+comment_len == tail.len()`（防止 EOCD 出现在注释里）。
2. 取 `cd_offset`（EOCD 16..20）；若为 `0xFFFFFFFF` 走 zip64：EOCD 前 20 字节找 `0x07064b50` locator，再跳 `rec_off` 读 56 字节 `0x06064b50` record，`cd_offset = rec[48..56]`。
3. `cd_offset` 前 24 字节 = `u64 size_of_block` + 16 字节 magic；magic 不匹配 → 无签名块（`Ok(None)`，不是错误）。
4. 合理性检查：`24..=64MiB`，且 `size+8 <= cd_offset`；随后 `start = cd_offset - size - 8`，校验块首 8 字节 == size。
5. `parse_block_pairs`（196–215）拆 `(id, value)`：从 pos 8 到 `len-24`，先 u64 长度再 u32 id，value = 去掉 id 的剩余；边界用 `len > end - pos` 而非 `pos + len > end`（防 u64 回绕）。
6. `block_certificates`（233–251）按 v2/v3 共同的长度前缀结构下钻：`signers → signer → signed data → (digests, certificates)`，每张证书是长度前缀的 DER。

**v1 路径**（51–82）：重新以 zip 打开，只取 `META-INF/` 下**顶层**的 `*.rsa / *.dsa / *.ec`（`l[9..].contains('/')` 排除子目录，大小写不敏感）；对每个文件跑 `pkcs7_certificates`（295–320）：`ContentInfo SEQ` → 第 2 个子项 `[0] EXPLICIT` → `SignedData SEQ` → 跳过 version/digestAlgorithms/encapContentInfo 三项后找 `0xA0`（certificates）→ 取其下 `0x30` 子项原文。

**跨方案去重**（`push_signer` 103–112）：以证书 DER 的 SHA-256 为键，同一张证书在 v1+v2+v3 中各出现一次时只保留一条。

**字段提取**（`describe_certificate` 353–386）：

- `dn_string`（346–351）把 x509-parser 的 DER 顺序 `C=.., O=.., CN=..` **反转**成 `CN=..., OU=..., O=..., C=..`，与 apksigner / keytool 一致。
- `serial_hex = raw_serial_as_string().to_uppercase()`。
- 指纹：`digests(der)`（`crates/core/src/hash.rs:27–32`，SHA-256/SHA-1/MD5 十六进制）→ `colon_hex`（35–41）→ 大写、每字节冒号分隔。
- 密钥算法/长度（358–372）：`RSA`/`EC` 用 `key_size()`；`DSA` 用 `y.len()*8`；`GOST` 无长度；未知（如 Ed25519）按 OID 名、长度 `None`。
- `signature_algorithm`：`oid_name`（322–342）映射 **17 个 OID**，含 `1.2.840.113549.1.1.1` RSA、`…1.1.11` SHA256withRSA、`1.2.840.10045.4.3.2` SHA256withECDSA、`2.16.840.1.101.3.4.3.2` SHA256withDSA、`1.3.101.112` Ed25519；未识别的 OID 原样输出点分字符串。

### 3.4 渲染（`pages.rs:915–1053`）

- 顶部状态行（920–941）：`field.computing` / `signature.disabled` / `signature.not_applicable`（归档包）/ `signature.failed`（`{error}`）。

## 5. 坑（按会踩到的概率排序）

1. **`protectionLevel` 是位掩码，不是枚举**。低 4 位是基类（0 normal / 1 dangerous / 2 signature / 3 signatureOrSystem / 4 internal），高位是标志。任何"把 `signature|privileged` 当字符串比较"的写法都会漏掉 900+ 条。存原始 u32 最稳。
2. **废弃标志位仍占位**。`0x20000 wellbeing`、`0x40000 documenter` 已废弃但位不能跳；漏掉会让所有更高位错位（参考实现为此留了 `high_protection_flags_are_aligned` 回归测试，`mod.rs:248–257`）。Dart 侧若只关心展示，可以不解析高位——但**不要**用"高位全清零"之外的假设。
3. **只有 143/1102 条有文案**。UI 必须容错：有保护级别无文案 → 不显示占位；无保护级别 → 标"应用/厂商自定义"；**不要**把没有文案的框架权限也标成"自定义"（参考实现用 `level.is_none()` 区分，`pages.rs:621–628`）。
4. **权限名不做归一化**。大小写敏感，`android.permission.` 前缀精确剥离；`com.*` 与 `android.intent.category.MASTER_CLEAR.permission.C2D_MESSAGE` 永远查不到文案。别用 `toUpperCase()` 做键——现在恰好全大写不代表将来是。
5. **`maxSdkVersion` 是字符串编码进来再拆的**。目标项目当前的 `apk_info.dart:1736–1738` **既没有** 处理 `uses-permission-sdk-23`，**也没有** 拼 maxSdk。移植时必须先补解析，否则参考实现的 `≤ API 32` 提示永远出不来。另外去重按**名字**，不要按"名字+maxSdk"。
6. **`sdk_version_text` 的未知分支是 `"99 ()"`**（空括号），`info.rs:480–485` 的测试就这么写的。移植时要决定是保留（与参考一致）还是改成 `"99 (未知)"`；顺带注意 API 37 有版本名但**没有发布日期**，UI 必须有 `_nodate` 分支。
7. **语言代码不是 BCP-47**。Android 用 `zh-rHK` / `sr-Latn` / `es-419`，BCP-47 用 `zh-HK`；`iw/in/ji` 映射到 `he/id/yi`；`--_--` 是"无语言限定"占位，排序要放最前。
8. **"key 齐全"不等于"翻译齐全"**。生成脚本对缺失翻译静默回退英文（`pick`，脚本 217–219），6 个语言文件的条目数才完全一致。若要做"是否已翻译"的判断，必须另存标记，别用"有没有 key"。
9. **风险分级是本产品策略，不是 Android 事实**。`dangerous` ≠ 高风险；`SYSTEM_ALERT_WINDOW` 是 `signature` 基类却被单独提到 Sensitive；`READ_CELL_BROADCASTS` 在 HIGH_RISK 里却没文案。移植时把 16+6 个名单当成**可更新配置**，别散进 if 链——目标项目 `PermissionCatalog.rulesVersion` 已经是这个模式，建议沿用。
10. **签名不验签**。参考实现明确不做摘要校验（`signature.rs:1–3`），文案也这么写。目标项目如果沿用 UI，**不能**出现"已验证/签名有效"字样，只能是"解析自内嵌证书"。
11. **v1 证书只在 `META-INF/` 顶层**。扫 zip 时排除子目录，否则会误把其他 DER 当证书；PKCS#7 里 `certificates` 是 `[0] IMPLICIT`，要跳过前三个字段再找 `0xA0`。
12. **签名块解析的边界条件**。EOCD 扫描要校验 `i+22+comment_len == tail.len()`（注释里会出现假 EOCD）；长度比较要用减法形式防 u64 回绕（参考实现两处注释指出了原 bug：`signature.rs:178`、`206`）；块大小上限 64 MiB。
13. **DN 顺序**。x509-parser / DER 顺序是 `C=.., O=.., CN=..`，apksigner / keytool 是 `CN=.., …, C=..`。参考实现反转了一次（`dn_string` 346–351）。Dart 侧若用别的库，先确认它给的是哪种，别反转两次。
14. **跨方案重复证书**。同一证书常同时出现在 v1/v2/v3 里，按 DER SHA-256 去重，否则签名者列表会重复三遍。
15. **windui 的 `{{}}`**。`i18n/android/*.toml` 里的 `{` 都写成 `{{`（占位符转义），转 JSON 时要还原成单花括号，否则文案里会出现双括号。
16. **`uses-feature` 的必需/可选语义**。`required="false"` → 可选；缺失该属性视为必需。两组合并展示时徽章不能搞反（`manifest.rs:73–82`）。
